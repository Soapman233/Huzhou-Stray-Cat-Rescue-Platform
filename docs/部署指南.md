# HZSCA 部署指南

> 从零开始把 HZSCA 平台跑起来。覆盖依赖服务、数据库初始化、后端启动、前端构建与小程序导入。

---

## 一、环境要求

| 依赖 | 版本 | 说明 |
|---|---|---|
| JDK | 17+ | 后端编译与运行 |
| Maven | 3.9+ | 或直接使用仓库自带的 `mvnw` |
| MySQL | 8.0+ | 业务数据库 |
| Redis | 6.x / 7.x | 缓存 |
| Node.js | 18+ | 前端构建 |
| Docker | 可选 | 用于一键启动 MySQL + Redis |
| 微信开发者工具 | 最新稳定版 | 运行小程序 |

---

## 二、启动依赖服务

### 方案 A：Docker Compose（推荐）

仓库根目录已提供 `docker-compose.yml`，支持**两种模式**：

#### A1. 只启动依赖服务（本地跑后端源码）

```bash
docker compose up -d
docker compose ps        # 等待 mysql / redis 均为 healthy
```

默认参数与 `application.yml` 保持一致：MySQL `root/1234`（库 `hzsca`，端口 `3306`）、Redis 无密码（端口 `6379`）。

#### A2. 全栈一键启动（含后端容器）

```bash
docker compose --profile full up -d --build
```

该模式会额外构建并启动后端容器 `hzsca-app`（镜像由
`hzsca-springboot/hzsca/Dockerfile` 多阶段构建：Maven 编译 → JRE 运行，非 root 用户）。

启动后：

- 后端接口：<http://localhost:8080>
- 接口文档：<http://localhost:8080/swagger-ui.html>

可通过环境变量覆盖默认配置（也可先复制 `.env.example` 为 `.env`）：

```bash
JWT_SECRET="不少于32字节的随机字符串" \
ALIPAY_ENABLED=false \
docker compose --profile full up -d --build
```

> 容器内 `DB_HOST` 已自动指向 `mysql` 服务名；`uploads/` 目录挂载到命名卷 `hzsca-uploads` 持久化。

#### 停止与清理

```bash
docker compose down            # 停止（保留数据）
docker compose --profile full down
docker compose down -v         # 停止并删除数据卷（谨慎）
```

#### 单独构建后端镜像

```bash
docker build -f hzsca-springboot/hzsca/Dockerfile -t hzsca-backend ./hzsca-springboot/hzsca
docker run -d --name hzsca-app -p 8080:8080 \
  -e DB_HOST=host.docker.internal -e DB_PORT=3306 \
  -e DB_USERNAME=root -e DB_PASSWORD=1234 \
  -e JWT_SECRET=不少于32字节的随机字符串 \
  hzsca-backend
```

> 首次构建需联网下载 Maven 依赖，耗时较长（约 3~5 分钟）；后续构建会复用依赖层缓存。

### 方案 B：手动安装

**Windows**

- MySQL：官网下载 MySQL Installer，安装时设置 root 密码为 `1234`；
- Redis：官方不提供 Windows 版，可选
  - 使用 **WSL2**：`wsl --install` 后在 Ubuntu 内 `sudo apt install redis-server && sudo service redis-server start`；
  - 或使用 Windows 移植版（如 Memurai / tporadowski/redis）解压后运行 `redis-server.exe`。

**macOS**

```bash
brew install mysql redis
brew services start mysql
brew services start redis
```

**Linux（Ubuntu/Debian）**

```bash
sudo apt update
sudo apt install -y mysql-server redis-server
sudo systemctl enable --now mysql redis
```

> 若 MySQL root 密码不是 `1234`，请通过环境变量 `DB_PASSWORD` 覆盖，无需改代码。

## 三、初始化数据库

```bash
# 1) 创建数据库（后端不会自动建库，需要先建空库）
mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS hzsca DEFAULT CHARACTER SET utf8mb4;"
```

**表结构无需手动导入** —— 应用启动时 `DbBootstrap` 会自动：

1. 检测核心表（`animals` / `users` / `activity` / `wx_user`）是否缺失，缺失则执行 `db/schema.sql`（17 张基础表，全部 `CREATE TABLE IF NOT EXISTS`，**不会删改已有数据**）；
2. 执行 `db/matching.sql`、`db/volunteer.sql` 补齐算法与志愿者相关表；
3. 写入猫咪特征与演示数据（`seed_cat_traits.sql`、`seed_admin_demo_data.sql`）；
4. 若 `admins` 表为空，创建演示管理员 `admin / admin123456`；
5. 创建支付订单表（`db/payment.sql`）；
6. **口令迁移**：把残留的明文口令统一升级为 BCrypt。

> 如需手动导入，也可按 `schema.sql` → `matching.sql` → `volunteer.sql` → `seed_*.sql` → `payment.sql` 顺序执行。

## 四、启动后端

### 开发模式

```bash
cd hzsca-springboot/hzsca

# 必须设置 JWT_SECRET（不少于 32 字节），否则启动直接报错
export JWT_SECRET="请替换为不少于32字节的随机字符串_ChangeMe_0123456789abcdef"
export DB_USERNAME=root
export DB_PASSWORD=1234

./mvnw spring-boot:run
```

Windows 用户可直接运行仓库根目录的 `start-backend.bat`（已内置上述环境变量设置）。

启动成功后：

- 接口地址：<http://localhost:8080>
- 接口文档：<http://localhost:8080/swagger-ui.html>

### 打包部署

```bash
cd hzsca-springboot/hzsca
./mvnw -o clean package -DskipTests      # 离线打包
java -jar target/hzsca-0.0.1-SNAPSHOT.jar \
     --server.port=8080
```

生产环境请通过环境变量或配置中心注入 `JWT_SECRET`、`DB_PASSWORD`、`ALIPAY_*` 等敏感项。

## 五、启动前端

```bash
cd hzsca-vue/hzsca
npm install
npm run dev        # 开发模式，默认 http://localhost:5173
npm run build      # 生产构建，产物在 dist/
npm run preview    # 本地预览构建产物
```

> 后端地址在 `src/config/config.js`（`baseURL` / `imageBaseURL`）中配置；Vite 已配置 `/api` → `http://localhost:8080` 代理。

## 六、运行微信小程序

1. 打开微信开发者工具 → 导入项目 → 选择 `hzsca-miniapp` 目录；
2. 修改 `utils/config.js` 中的 `BASE_URL` 为后端地址；
3. 本地调试：**详情 → 本地设置 → 勾选「不校验合法域名」**；
4. 真机预览 / 上线：`BASE_URL` 必须替换为已在小程序后台配置的 **HTTPS 合法域名**，否则真机无法请求。

## 七、首次运行检查清单

| # | 检查项 | 期望结果 |
|---|---|---|
| 1 | MySQL 是否可达 | `mysql -uroot -p1234 -h127.0.0.1 -e "SELECT 1"` 正常返回 |
| 2 | `hzsca` 库是否已创建 | `SHOW DATABASES;` 中存在 `hzsca` |
| 3 | Redis 是否可达 | `redis-cli ping` 返回 `PONG` |
| 4 | 端口是否被占用 | 8080（后端）、5173（前端）、3306、6379 未被占用 |
| 5 | `JWT_SECRET` 是否设置 | 未设置时后端会抛 `security.jwt.secret is required` |
| 6 | 表结构是否自动创建 | 启动日志出现 `检测到核心表缺失，执行 db/schema.sql`（首次） |
| 7 | 演示数据是否就绪 | `SELECT COUNT(*) FROM animals;` 返回 38 |
| 8 | 支付表是否创建 | `SHOW TABLES LIKE 'payment_order';` 有结果 |
| 9 | 静态图片是否可访问 | 浏览器打开 <http://localhost:8080/cats/1.jpeg> 显示图片 |
| 10 | 管理员能否登录 | `admin / admin123456`（全新库）可登录后台 |

## 八、常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动报 `Port xxx was already in use` | 端口被占用；可用 `--server.port=8081` 指定其他端口 |
| 启动报 `security.jwt.secret is required` | 未设置 `JWT_SECRET`，或长度不足 32 字节 |
| 启动报 `must be at least 32 bytes` | `JWT_SECRET` 太短，换一个更长的随机串 |
| 页面图片全部 404 | 后端未启动，或前端 `imageBaseURL` 指向错误 |
| 登录提示「登录已过期」 | JWT 过期（默认 7 天），重新登录即可 |
| 捐助页显示「Mock 演示模式」 | 未配置支付宝密钥，属预期行为，见《支付接入指南》 |
| `Access denied for user 'root'` | 数据库密码与 `DB_PASSWORD` 不一致 |
| 中文乱码 | 数据库字符集需为 `utf8mb4`（docker-compose 已配置） |
| **更换图片后页面显示占位图** | `CatsServiceImpl` 对猫咪数据有 24 小时 Redis 缓存，缓存中保存的是旧的图片路径。执行 `redis-cli -p 6379 DEL cats:all cats:adoptable` 清理后刷新即可 |
| 前端图片地址不对 | 修改 `hzsca-vue/hzsca/src/config/config.js` 的 `imageBaseURL`；小程序端修改 `utils/config.js` 的 `BASE_URL` |
