# 支付宝沙箱支付接入指南

> 本文档说明 HZSCA 平台「爱心捐助」支付模块的设计、接入与调试方式。
> 项目**未引入任何第三方支付 SDK**，签名与验签全部使用 JDK 内置 `java.security`（RSA2 / SHA256withRSA）实现，便于离线构建与原理讲解。

---

## 一、模块设计

```
前端 donate.vue
   │  POST /api/payment/orders { amount(分), purpose, remark }
   ▼
PaymentController  ──►  PaymentService
                          │
                          ├── 未配置密钥 → Mock 模式：仅落库，前端用 mock/pay 直接置为已支付
                          └── 已配置密钥 → 支付宝沙箱
                                  ├─ 构造 alipay.trade.page.pay 收银台 URL（RSA2 签名）
                                  ├─ 浏览器跳转收银台完成支付
                                  ├─ 异步通知 notify_url → 验签 → 幂等置为 PAID
                                  └─ 主动查单 alipay.trade.query → 兜底同步状态
```

### 核心类

| 类 | 路径 | 职责 |
|---|---|---|
| `PaymentController` | `controller/PaymentController.java` | REST 接口 |
| `PaymentService` / `PaymentServiceImpl` | `service/` | 订单生命周期、状态机、Mock 降级 |
| `AlipayProperties` | `config/AlipayProperties.java` | `alipay.*` 配置绑定 |
| `AlipaySignUtils` | `utils/AlipaySignUtils.java` | RSA2 签名 / 验签 / 密钥解析 |
| `PaymentOrder` | `entity/PaymentOrder.java` | 订单实体 |
| `payment.sql` | `resources/db/payment.sql` | 订单表 DDL（启动自动建表） |

### 订单状态机

```
CREATED ──跳转收银台──► PAYING ──支付成功──► PAID
   │                      │                  │
   │                      └── 超时/关闭 ──► CLOSED
   └── 构造失败 ──► FAILED
```

- **幂等**：`updateStatusIfCurrent` 仅在「当前状态 ∈ 允许集合」时才更新，重复通知不会重复置位；
- **金额校验**：通知金额与订单金额（分）不一致时直接判为失败；
- **归属校验**：查单/同步/模拟支付均校验订单归属于当前登录主体，防止越权。

## 二、沙箱账号与应用申请

1. 访问支付宝开放平台沙箱环境：<https://open.alipay.com/develop/sandbox/app>
2. 用支付宝账号登录 → 进入**沙箱应用**，可看到系统自动分配的：
   - **APPID**（沙箱应用 ID）
   - **应用私钥 / 应用公钥**
   - **支付宝公钥**
   - **沙箱买家账号**（用于付款测试，含登录密码与支付密码）
3. 在「接口加签方式」中选择 **公钥模式**，签名算法选 **RSA2**。

> 沙箱环境与生产环境完全隔离，不会产生真实资金流动。

## 三、生成 RSA2 密钥

方式一（推荐）：使用**支付宝开放平台密钥工具**（Windows/macOS 客户端），选择「RSA2」→「PKCS#8」生成，工具会输出应用私钥与公钥。

方式二：使用 OpenSSL 手动生成：

```bash
# 生成 PKCS#8 私钥（2048 位）
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out app_private_key.pem

# 导出公钥
openssl rsa -in app_private_key.pem -pubout -out app_public_key.pem

# 去掉 PEM 头尾与换行，得到单行 Base64（填入配置）
grep -v "KEY-----" app_private_key.pem | tr -d '\n'
```

把**应用公钥**粘贴到沙箱应用的「接口加签方式」中保存，平台会返回**支付宝公钥**（注意：验签要用「支付宝公钥」，不是应用公钥）。

## 四、配置

编辑 `hzsca-springboot/hzsca/src/main/resources/application.yml` 的 `alipay` 段，或通过环境变量注入：

```bash
export ALIPAY_ENABLED=true
export ALIPAY_APP_ID=你的沙箱APPID
export ALIPAY_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----...（可含换行）"
export ALIPAY_PUBLIC_KEY="-----BEGIN PUBLIC KEY-----...（支付宝公钥）"
export ALIPAY_NOTIFY_URL=http://你的公网地址/api/payment/alipay/notify
export ALIPAY_RETURN_URL=http://localhost:5173/hzsca/donate/result
```

| 配置项 | 说明 | 默认值 |
|---|---|---|
| `alipay.enabled` | 是否启用真实沙箱 | `false` |
| `alipay.gateway` | 沙箱网关 | `https://openapi-sandbox.dl.alipaydev.com/gateway.do` |
| `alipay.app-id` | 沙箱 APPID | 空 |
| `alipay.merchant-private-key` | 商户应用私钥（PKCS#8） | 空 |
| `alipay.alipay-public-key` | 支付宝公钥（验签用） | 空 |
| `alipay.notify-url` | 异步通知地址（**需公网可达**） | `http://localhost:8080/api/payment/alipay/notify` |
| `alipay.return-url` | 同步回跳地址 | `http://localhost:5173/hzsca/donate/result` |
| `alipay.min-amount` / `max-amount` | 单笔金额上下限（分） | `100` / `5000000` |

> **降级规则**：只要 `enabled=false` 或任一密钥为空，系统自动进入 **Mock 演示模式**，无需任何账号即可跑通「下单 → 支付 → 结果页」全流程。

## 五、接口清单

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/payment/config` | 公开 | 返回 `mock`、金额上下限、累计捐助金额 |
| POST | `/api/payment/orders` | 登录 | 创建订单，返回 `outTradeNo / payUrl / mock` |
| GET | `/api/payment/orders/{outTradeNo}` | 登录（本人） | 查询订单状态 |
| POST | `/api/payment/orders/{outTradeNo}/sync` | 登录（本人） | 主动向支付宝查单并回写状态 |
| POST | `/api/payment/orders/{outTradeNo}/mock/pay` | 登录（本人，仅 Mock） | 模拟支付成功 |
| GET | `/api/payment/alipay/return` | 公开 | 同步回跳（仅提示，状态以异步通知为准） |
| POST | `/api/payment/alipay/notify` | 公开 | 异步通知，**必须返回纯文本 `success`** |

创建订单请求体：

```json
{ "amount": 3000, "purpose": "donate", "remark": "加油" }
```

> `amount` 单位为**分**（3000 = 30.00 元）。

## 六、本地联调（异步通知）

支付宝的异步通知需要**公网可达**地址，本地开发可用内网穿透：

```bash
# 以 cpolar / ngrok / frp 为例，将 8080 暴露到公网
ngrok http 8080
# 得到形如 https://xxxx.ngrok-free.app 的地址，设置：
export ALIPAY_NOTIFY_URL=https://xxxx.ngrok-free.app/api/payment/alipay/notify
```

然后在沙箱买家账号中完成付款，观察后端日志：

```
收到支付宝异步通知 outTradeNo=HZSCA...
订单已支付 outTradeNo=HZSCA..., tradeNo=...
```

> 即使异步通知不可达，前端结果页也会**每 3 秒轮询**一次 `/sync`（最多 60 秒），由后端主动查单兜底，保证状态最终一致。

## 七、测试步骤

1. 以 `ALIPAY_ENABLED=false` 启动，验证 Mock 链路：捐助页 → 选金额 → 确认 → 结果页 → 点「模拟支付成功」→ 状态变 `PAID`；
2. 配置好沙箱密钥后重启，捐助页「Mock 演示模式」标签消失，点确认后**跳转到支付宝沙箱收银台**；
3. 使用沙箱买家账号付款，付款成功后回跳结果页；
4. 查询数据库确认订单状态与 `trade_no`：

```sql
SELECT out_trade_no, amount, status, trade_no, pay_time FROM payment_order ORDER BY id DESC LIMIT 5;
```

## 八、对账与审计日志

资金类业务必须假设「异步通知会丢失」，因此除前端轮询外，服务端还提供兜底对账能力。

### 8.1 审计日志表 `payment_audit_log`

所有订单状态变更都会写入审计日志，便于问题排查与资金追溯：

| 字段 | 说明 |
|------|------|
| `out_trade_no` | 关联订单号（任务级日志可为空） |
| `action` | `CREATE` / `PAY` / `NOTIFY` / `SYNC` / `RECONCILE` / `CLOSE` / `FAIL` |
| `from_status` / `to_status` | 状态变更前后 |
| `success` | 本次操作是否成功（验签失败、金额不一致等会记为 false） |
| `detail` | 详细信息（原因、报文摘要、错误信息） |

> 设计原则：**审计写入失败绝不影响主流程**，异常会被吞掉并降级为告警日志。

### 8.2 定时对账任务 `PaymentReconcileTask`

默认每天 **凌晨 02:30** 执行（`@Scheduled`），做三件事：

1. **主动查单补记**：把停留超过 30 分钟仍未支付的订单逐笔调用 `alipay.trade.query`，
   若支付宝侧已支付则补记状态（解决「通知丢失导致订单状态不更新」）；
2. **超时关单**：创建超过 24 小时仍未支付的订单置为 `CLOSED`，避免脏数据堆积；
3. **审计一致性检查**：找出「已支付但缺少 `PAY`/`NOTIFY` 审计记录」的订单并告警。

配置项（`application.yml`）：

```yaml
payment:
  reconcile:
    enabled: true                # 关闭定时任务
    cron: "0 30 2 * * ?"         # 执行时间（每天 02:30）
    pending-minutes: 30          # 超过该时长才纳入对账
    close-hours: 24              # 超过该时长自动关单
    batch-size: 200              # 单次处理上限
```

### 8.3 管理端接口（需 admin 角色）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/admin/payment/reconcile` | 手动触发一次对账，返回处理摘要 |
| GET | `/api/admin/payment/orders/{outTradeNo}/audit` | 查询某笔订单的完整审计轨迹 |

手动对账返回示例：

```json
{
  "code": "200",
  "data": {
    "mode": "MOCK",
    "checked": 12,
    "repaired": 2,
    "closed": 3,
    "paidTotal": 15,
    "missingAudit": 0,
    "finishedAt": "2026-10-12T13:25:02"
  }
}
```

> `repaired` 表示通过主动查单补记成功的订单数；`missingAudit` 表示发现审计缺失的异常订单数。

## 九、常见问题

| 现象 | 排查方向 |
|---|---|
| 启动后仍是 Mock 模式 | `alipay.enabled` 是否为 `true`；三项密钥是否都非空 |
| 收银台报「验签失败」 | 私钥格式是否为 PKCS#8；是否误把「应用公钥」当私钥使用 |
| 通知一直 `failure` | 验签用的是**支付宝公钥**吗；金额是否与订单一致；`notify_url` 是否公网可达 |
| 支付成功但订单未变更 | 通知未达 + 前端未轮询到；可手动调 `/sync` 主动查单 |
| 沙箱网关 404 | 新版沙箱网关为 `openapi-sandbox.dl.alipaydev.com`，旧版为 `openapi.alipaydev.com`，按账号类型选择 |

## 十、生产化建议

- 将 `ALIPAY_ENABLED` 与密钥改为**密钥管理服务**注入，严禁硬编码入库；
- `notify_url` 必须使用 **HTTPS** 并校验来源；
- 对账任务已内置（见第八章），生产环境建议**额外接入支付宝官方对账单下载接口**做逐笔核对；
- 捐助金额、订单状态建议保留完整审计日志（本项目已提供 `payment_audit_log`）并设置告警；
- 如需接入微信支付，可新增 `WechatPayService` 实现同一 `PaymentService` 接口，前端无需改动。
